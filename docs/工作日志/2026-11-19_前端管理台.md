## 设计

- **工程**：`frontend/` 独立目录，Vite dev 端口 5173；`/api` 走 vite 代理到 8080
  ——用代理而不是后端开 CORS：请求同源（无预检开销）、生产环境 nginx 同架构、后端零放宽
- **技术选型**：Vue3 组合式 API + Element Plus（全量引入，教学项目不折腾按需）+ Pinia + vue-router + axios
- **请求封装**：axios 实例 baseURL=/api；响应拦截统一解包 `Result{code,message,data}`；
  code=40100 或 HTTP 401 → 清 token 跳登录；其余非 0 → ElMessage 提示
- **用户态**：Pinia user store（token/用户名/角色/stationId），token 存 localStorage 持久化；
  路由守卫：无 token 且非登录页 → 重定向 /login
- **页面**：登录页、布局（侧边菜单 + 顶栏退出）、电站管理（CRUD+分页，ADMIN 专属按钮）、
  日统计查询、工单管理（角色按钮）、考核结果（本月表格）
- **后端配合改动**：补 `GET /api/assessment/month/{month}` 查询接口（此前 0-5 无 HTTP 入口，
  页面要展示必须有；VO 带电站编号/名称，接口内拼装不返回裸表结构）

## 所用技术

- 后端：MyBatis-Plus 双查询拼装 VO（无 XML join）

### 踩坑记录

- npm 默认装到了 vite 8 / vue-router 5：vite 8 要求 Node ≥20.19（本机 20.15 起不来），且 vue-router 5 偏离教学资料 → package.json 锁 `vite@^5.4`、`@vitejs/plugin-vue@^5.2`、`vue-router@^4.6` 后重装
- vite 不认 `@/` 别名（模板自带配置只有 vue 插件）→ vite.config.js 补 `resolve.alias: '@' → ./src`
- 中文乱码沿用旧结论：git-bash curl 发中文 JSON 会 GBK 化导致后端 500，验证一律用 ASCII 请求
- **雪花 ID 精度坑（浏览器验收时暴露）**：电站 ID 是 19 位雪花 ID，超过 JS 安全整数 2^53-1（16 位）。后端原样输出 JSON 数字，浏览器 parse 时丢精度——实测 9 个电站 ID 在 JS 里只剩 2 个值（WF001-3 叠成 `...0600`，WF004-9 叠成 `...2300`），症状是电站下拉框塌缩成一个选项、日统计按 ID 查询返回空。修复：后端 `JacksonConfig` 全局 Long→String 序列化（业界标准做法），前端 id 全程当字符串用，Spring 参数绑定自动转回 Long；前端仅分页 total 需 `Number()` 转回数字。教训：**凡是含雪花 ID 的接口，curl 验证时也要看 JSON 里 id 的形态**，只看 code/行数发现不了
- **日统计页空表（漏调 onMounted）**：StatsView 定义了 `loadStations` 却从未调用（import 了 onMounted 但没写 `onMounted(loadStations)`），页面从进来到离开不发任何请求——下拉框"无数据"、点查询"请先选择电站"。排查走了弯路：curl 复现的是"假设已调用"的流程，而不是代码的真实行为——**先读代码再猜环境**。修复：补 `onMounted(loadStations)`，并给页面加了显式「查询」按钮（下拉框选同一电站不触发 change，必须给手动重查入口）
